# Blog migration preview

The TanStack Start version of the blog lives here while the root Eleventy site remains the production build. The root `.eleventyignore` excludes this directory. Cloudflare Pages settings and the root Makefile have not been changed.

## Run locally

Use Node 22.12 or newer and npm. From this directory:

```sh
npm ci
npm run dev
```

Development runs at http://127.0.0.1:4187. To inspect the complete static artifact:

```sh
npm run build
npm run preview
```

The static preview runs at http://127.0.0.1:4188. The generated artifact is `dist/client/`; `dist/server/` is used during prerendering. The static preview serves the generated 404 page for missing paths, including `/work/`.

## Content and presentation

The `../posts/<slug>/index.md` files are the source of truth for both builds. Titles, descriptions, dates, URLs, and colocated images are reused. Key's passphrase and TOTP sections are now standalone follow-ups, linked from the original article.

Each post directory can contain one `index.md` or `index.mdx`. Both require YAML frontmatter with `title`, `description`, and `date` (`YYYY-MM-DD`). Markdown remains plain Markdown, so literal braces and comparison operators in prose do not acquire JSX meaning. MDX supports JSX and component imports, including the `@/` alias into this app. Restart development after adding a post or changing its metadata or colocated assets; article body edits use Vite's normal module updates.

An article with `interactive: hmac` in its frontmatter shares one browser-only example across its marked figures. Standalone images ending in `#interactive-hmac-base32`, `#interactive-hmac-setup`, `#interactive-hmac`, `#interactive-hmac-clock`, `#interactive-hmac-select`, `#interactive-hmac-mask`, `#interactive-hmac-number`, or `#interactive-hmac-remainder` opt into the corresponding live view. The Markdown plugin makes them figures, and the article renderer enhances them after hydration when Web Crypto is available. Server-rendered HTML, no-JavaScript reading, and the Eleventy build retain the SVG fallbacks. The clock runs continuously, derives the counter from the current Unix time every second, and recalculates HMAC on window changes. Setup uses one read-only conversion card: the 20 browser CSPRNG bytes, an encoding arrow, and their 32-character Base32 representation. A button in its header generates another seed. The next figure builds a matching `otpauth` URI and scannable QR. The QR encoder loads only for that live figure, and QR decoding is verified independently in the browser tests. The HMAC figure uses two shadcn input cards: Base32 text decodes back to key-byte tiles, while the decimal clock counter is encoded into eight message-byte tiles, most significant byte first. Byte encoding appears here rather than in the clock figure. These byte sequences feed every later calculation. The selection figure leads with the 20-byte digest and its highlighted four-byte slice. A numbered guide below follows the last byte at position 19, its rightmost four bits and 8/4/2/1 weights, then the resulting starting position. The selector byte and payload have distinct labelled highlights, all derived from the same live result. The mask figure aligns all four selected bytes before and after clearing the first bit. A separate number figure follows the place-value explanation, with four aligned byte contributions that sum to one decimal number. The final card splits that number into muted whole millions and six code positions, preserving and identifying zero padding. The clock strip moves equal 30-second windows beneath a fixed now marker, with the current Unix value directly above it and one ungrouped timestamp at each boundary. The raised, labelled active window contains that value; there is no separate current-window readout or pause control. Reduced-motion mode updates the same labelled view without animated transitions. State remains scoped to the article; generating a new secret does not send requests or change the page URL or browser storage. Following the explicit setup link or scanning the QR transfers the demo seed to the reader's authenticator.

`scripts/markdown.ts` configures GFM tables, frontmatter, heading normalization, and build-time Shiki highlighting. The article layout owns h1; body headings start at h2 while preserving their relative levels. Unlabelled and unknown-language fences render as plain code with the same controls. Shiki is a build dependency and is not imported by browser components.

`src/typeset.css` is the official stylesheet from https://ui.shadcn.com/typeset.css. The `typeset-article` preset and app theme live in `src/styles.css`. The Base UI `base-nova` Button and Code Block sources came from the shadcn CLI. The unused client highlighter generated by the registry was removed; Code Block's copy control was extended to announce clipboard failures.

Article rendering supports keyboard-scrollable tables, hidden labels for the existing unnamed row-index headers, code copying and wrapping, system/light/dark themes, and a skip link. Article content is code-split away from the homepage. All article bodies currently share the article-route chunk.

Card accents and description sizes are explicit component props. Diagram CSS owns the data layout and color tokens. The writing index uses a native list, with each separator inside its corresponding list item.

The theme toggle subscribes to the document's theme attribute with `useSyncExternalStore`, using the same initial snapshot for server rendering and hydration. The root route supplies the copyright year as loader data so the initial browser render reuses the server's value.

Generated public assets and the content manifest are recreated by development, typechecking, and builds. Edit the original posts/assets or maintained source files rather than those generated copies. Font and shadcn notices are copied into the static artifact's `licenses/` directory; Vite also generates bundled dependency notices.

## Validation

```sh
npm run check
npm run build
npm run test:browser
```

The checks cover formatting, linting, TypeScript, content metadata, and Markdown/MDX compilation. Playwright exercises the static artifact in desktop and mobile Chromium, including client navigation, all existing articles and images, axe accessibility checks, theme persistence, exact code copying, clipboard denial, wrapping, no-JavaScript reading, preview indexing, and 404 delivery. Install Playwright's Chromium browser if it is not already available: `npx playwright install chromium`.

Oxlint enables React and JSX accessibility correctness rules alongside its default plugins. Warnings and unused suppression comments fail the lint command. Inline exceptions are limited to the browser-only TOTP initialization after hydration, labelled data and field groups, accessible inline SVG, keyboard-scrollable code and tables, Safari's explicit list roles, and input addons that forward pointer focus to a separately keyboard-accessible input. Each exception names its rule and explains the behavior it preserves. Browser tests also cover hydration when the browser reports a different year from the prerendered page.

The dependency audit currently reports six low/moderate advisories in the development-only shadcn CLI dependency chain. The frontmatter plugin uses the patched 6.0.0 release. Recheck the CLI upstream rather than applying npm's proposed breaking downgrade to shadcn 1.0.0.

## Before production cutover

This is an unindexed preview. HTML metadata, `robots.txt`, and `_headers` prevent indexing. There is deliberately no deploy command or new Cloudflare configuration.

Before changing Pages, review the design and authoring workflow, add a production indexing/sitemap configuration, review canonical and sharing metadata, verify the final hosting headers and 404 behavior, and run the build/browser checks against that production artifact. Existing URLs, including the published `key-secret-mananger` spelling, must remain reachable. Keep the Eleventy build available until the migration is accepted.
